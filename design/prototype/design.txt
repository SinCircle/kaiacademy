数学问题分配与共享系统 · 设计文档
================================

【一、系统定位】
面向数学研究/学习社区的协作平台，用类 GitHub 的方式管理数学问题及其求解过程，
并通过讨论加速协作。核心目标：方便社区成员互相分享数学问题、共享进度、加速研究。

两大主线功能：
1. 共享、管理数学问题（类 GitHub 仓库管理，所有操作围绕数学）
2. 经验交流分享（聊天）

与普通题库的区别：不只是存问题，还要让"谁在做、做到哪、用什么方法"可见，
协调多人推进，把大目标拆成子问题分头攻克。


【二、核心设计决策】
· 访问范围：邀请制。成员在个人中心持有邀请名额，可发放邀请码；邀请关系形成推荐树。
  名额获取/增长规则：待设计（系统尚在启动阶段）。

· 分配机制：自主认领为主。成员自行挑题认领，系统显示"谁在做"，
  不做指派、不做锁定。

· 认领模式：多人并行。同一问题可多人同时认领、各自独立尝试、互不阻塞。
  防重复的承诺边界：系统只提示"谁在做"，不判定、不合并、不禁止——
  是否值得并行由成员自行判断。

· 问题结构：DAG。子问题可属多个父问题；系统防环。
  依赖的表示：父子边可着色。同一颜色的一组边 = 一组充分条件（组内合取、组间析取）。
  一个引理若支持多个充分组合，就为它画多条边，分属不同颜色。

· 治理模式：问题由创建者管理。结构、状态、合并等管理决定由创建者做出，
  创建者可将他人加入共同管理权限；成员对任意问题的贡献（提交解答）是开放的，
  但"采纳与否"由创建者把关。

· 设计原则：当前定位为轻量管理工具。自动化（状态级联、自动检测、精细权限）
  一律后置，先把人工流程跑通。


【三、核心实体】

1. 问题（Problem）—— 相当于仓库
   · 题面：富文本 + LaTeX
   · 元数据：领域标签、难度、来源、状态
   · 状态：未开始 / 进行中（有人认领且未完成）/ 已解决 / 已搁置
   · 题面版本历史（可追溯修订）
   · 关系：父子边（DAG，可着色分组）、横向关联（变体/推广/等价命题，非结构边）
   · 管理：创建者 + 受邀共同管理员

2. 认领 / 尝试（Attempt）—— 相当于分支 / PR
   · 认领即创建一条 Attempt："我在用这个方法解这道题"
   · 一个问题可同时有多条 Attempt（不同人、不同方法）
   · 内容：思路、中间结论、引用其它问题、最终证明；富文本 + LaTeX
   · 版本历史（commit 式修订）
   · 生命周期：草稿 → 进行中 → 提交评审 → 已合并 / 已归档 / 已搁置
   · 可被评论（评审式）

3. 成员（Member）
   · 专业领域标签、个人简介
   · 邀请关系树（邀请了谁、被谁邀请）
   · 邀请名额（规则待设计）
   · 贡献统计：解题数、被合并解答数、创建问题数、邀请数等
   · 活跃度

4. 讨论（Discussion）—— 聊天
   · 每个问题一个讨论区，嵌在问题页下方
   · 每条 Attempt 可评论（评审式）
   · 全局 / 按领域的交流区：消息内可引用（@）问题，点击跳转到该问题的讨论区
   · 暂不做私信，先聚焦公开讨论


【四、关键机制】

1. 邀请与信任
   · 成员用邀请名额生成邀请码发给被邀请人
   · 邀请关系形成推荐树，作为成员关系的结构记录
   · 名额规则待设计（启动阶段）

2. 认领与防重复
   · 认领 = 创建 Attempt + 在问题上显示"这些人正在做"
   · 不阻止并行；可见性即防重复手段的全部
   · 认领可放弃（搁置）或完成（Attempt 提交/合并）
   · 长期无进展的 Attempt 可被标记提醒（非强制释放）

3. DAG、着色与进度
   · 添加父子边时检查无环（不能形成循环依赖）
   · 边可着色；同一颜色的边集 = 一组充分条件
   · 状态变化全部手动：创建者手动判定、手动标记，不做自动级联、不做自动检测、
     不做状态上锁
   · 颜色与进度仅作辅助显示（如按色高亮某组子问题的现状），不参与状态判定
   · 横向关联不参与状态推导，仅作引用导航

4. 解答评审、合并与撤销
   · 任何成员可对任何问题提交 Attempt；创建者/共同管理员决定是否合并为"已采纳解答"
   · 一题可采纳多条解答（代表不同方法），不强制单一标准答案
   · 撤销：创建者手动撤销已合并解答、将问题状态改回；是否告知引用方由其自行处理

5. 变更与治理（PR 制）
   · 对问题的任意变更以 PR 形式提出：题面修订、父子边增删/着色、解答合并、状态判定
   · 任何成员均可提案；由创建者/共同管理员评审后合并或拒绝
   · 问题创建者可转让所有权、添加共同管理员
   · 精细权限（如跨问题边的归属、谁可删他人引用的边）：后续版本再做


【五、GitHub 类比映射】
   仓库        →  问题
   commit      →  题面/解答的版本修订
   branch/fork →  一条 Attempt
   PR          →  对问题的任意变更提案（题面/结构/解答），创建者合并后生效
   issue       →  待分解的开放问题 / 讨论
   star/watch  →  关注问题进展
   依赖        →  DAG 父子边（可着色）


【六、权限模型】（高信任社区，从简）
   · 成员（默认）：创建问题、认领、向任何问题提交 Attempt、以 PR 形式提议对他人问题的变更、
     评论、聊天、发放邀请（若有名额）
   · 创建者/共同管理员：合并/拒绝 PR（题面、结构、解答）、判定状态、撤销、转让
   · 管理员：全局管理、邀请名额调整、封禁等


【七、检索与浏览】
   · 按领域、难度、状态、是否有进行中认领过滤
   · 题面全文搜索
   · DAG 图谱可视化浏览（展开/折叠、进度条、状态着色、充分条件组按色高亮）


【八、待定 / 后续】
   · 邀请名额的获取与增长规则
   · 是否需要解题的形式化验证（目前仅人工评审）
   · 权限管理细化（跨问题边的归属、撤销权）
   · 状态自动化（依赖回退的检测与级联）
   · 通知系统、私信、移动端等
