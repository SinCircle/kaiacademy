# 丐院 · 正式版产品决策

## 定位

丐院是面向数学研究与深度学习社区的问题协作站点。它不是传统题库，也不把研究过程拆成复杂的项目管理对象；系统只负责让问题、参与者与公开讨论清楚可见，使不同思路能够并行发生。

首要原则是奥卡姆剃刀：如非必要，勿增实体。后续对话中的简化决定优先于早期 `design.txt`。

## 视觉

- 最终名称为“丐院”。
- 采用“公理黑白”方向：黑、白、灰为主，少量状态色仅用于传达信息。
- 排版克制、专业、朴素；标题不过度放大，不使用装饰性编号和解释标签。
- 卡片无阴影、无悬浮位移，以边框变化强调交互。
- 需要图标时统一使用专业图标，不允许用字符代替图标。
- 全站滚动条不占用布局宽度，内容展开时主体不得左右抖动。
- 桌面端与移动端都必须可用。

## 正式版模型

正式版不设置 Attempt、需解决的问题、证明分支、工作区、DAG、推进时间线、当前草稿或 Handoff 等独立实体。

核心对象只有：

1. 成员
2. 问题
3. 成员与问题之间的状态关系
4. 讨论消息
5. 邀请码
6. 按问题归组的动态通知

## 访问与账户

- 未登录访客只能访问首页、登录、注册和难题列表。
- 未登录访客不能进入问题详情；尝试访问其他页面时转到登录页。
- 注册字段固定为：邀请码、邮箱、邮箱验证码、用户名、密码、确认密码。
- 验证码通过 Resend 真实发送；邀请码必须先通过服务端校验，错误或已使用的邀请码不触发邮件。
- 注册邮箱暂限 `mails.ucas.ac.cn`、`gmail.com`、`outlook.com`、`qq.com` 与 `163.com`。
- 新成员默认拥有 0 个邀请名额。
- 邀请码一次性使用。
- 每名成员同时只能持有一个尚未使用的邀请码；旧邀请码被使用前，前后端都不允许再次生成。
- 超级管理员进入其他成员个人页时，可以修改其可用邀请额度。
- 成员本人只能查看额度、生成邀请码和复制邀请码，不能修改额度。
- 成员可上传不超过 10 MB 的图片，在浏览器内框选方形头像并确认；确认后服务端再次压缩为约 100 KB 的 WebP，再写入对象存储。

## 问题

- 问题包含标题、Markdown/LaTeX 正文、背景、标签、状态、创建者和时间信息。
- 问题状态只有“开放”和“已解决”；列表默认展示全部问题，卡片上仅对开放问题显示状态标记。
- “领域”与“标签”合并为同一套标签系统。
- 标签输入支持已有标签模糊匹配、键盘选择、回车确认和创建新标签。
- 新标签持久保存，并可以在搜索中命中。
- 搜索覆盖标题、正文、背景和标签。
- 难题列表支持按标签、状态、参与关系和推进时间筛选；推进时间为可取消的单选，其余条件可多选。筛选区域默认折叠，桌面端双栏、移动端单栏。
- 管理员和超级管理员可以置顶问题；置顶问题始终排在普通问题之前。
- 发布页和设置页使用完整宽度单栏表单，返回入口位于内容上方。

## 问题关系与权限

成员相对一个问题只有三种状态：

1. 旁观
2. 关注
3. 参与

状态按照“旁观 → 关注 → 参与 → 旁观”循环切换。参与自动包含关注，但参与者不会重复出现在关注者列表。

- 创建者、管理者和已有内容被采纳的成员必须保持参与，不能退出。
- 右栏只展示“参与者”和“关注者”。
- 创建者、管理者和被采纳者通过专属图标识别，不增加重复文字分组。
- 创建者可以任命或取消管理者、采纳或取消采纳消息、修改问题状态。
- 问题管理者可以增删参与者，并删除该问题下的评论；以后再扩展其他权限。
- 普通成员只能维护自己的关系状态和自己的讨论内容。

站点角色分为普通成员、管理员和唯一的超级管理员。超级管理员可以任命或撤销普通管理员；普通管理员与超级管理员均可进入问题管理页，人员管理、角色任命和邀请额度调整只属于超级管理员。问题与人员删除均为永久删除，并必须经过二次确认。

## 讨论即工作区

- 不再设置独立工作区，所有协作直接发生在问题页左栏的讨论区。
- 消息支持 Markdown、行内公式和块级公式。
- 任意登录成员都可以给任意消息（包括自己的消息）标记“解法”“见解”或“反例”；同一消息同时只有一种标签，再次选择当前标签即取消。
- 标签显示在消息正文下方，讨论区可以筛选全部、已标记或某一具体标签。
- 创建者可以采纳或取消采纳任意消息。
- 采纳消息后，对应作者在参与者列表中同步显示被采纳图标，并锁定为参与状态。
- 回复默认折叠，点击后展开。
- 支持多层嵌套；每一层每次最多显示 50 条，其余通过“展开更多”继续加载。
- 每条消息可以“顶”；同级消息按采纳状态优先、顶数降序排列。
- 作者可以隐藏自己的消息。隐藏后作者看到灰色的整条回复分支，普通成员看不到该消息及其子评论；问题创建者、问题管理者和站点管理员仍可查看灰色分支以便管理。
- 问题创建者、问题管理者和站点管理员可以在二次确认后永久删除一条消息及其全部子评论。
- 回复关系线从父级头像下方开始，在最后一个同级回复头像处结束。
- 主讨论输入框和行内回复输入框使用统一视觉：默认单行垂直居中，聚焦或输入后展开。

## 个人页与邀请

- 个人简介位于上方，资料、专业标签和参与问题清楚分区。
- 问题列表通过顶部标签切换“所有参与”“创建的问题”“足迹”“互动过的问题”。“所有参与”包含创建、参与和关注的问题；足迹仅本人可见；互动包含评论或点过“顶”的问题。
- “更换头像”只在本人进入编辑资料状态后出现，框选并确认前不会替换现有头像。
- 邀请区域紧跟个人资料，展示可用额度、一次性邀请码及生成入口。
- 超级管理员查看他人个人页时额外显示邀请额度修改控件。

## 动态通知

- 顶栏右侧设置消息菜单和未读数量。
- 动态按问题归组，而不是逐条平铺。
- 每组显示问题标题、最新动态摘要、时间和未读数量。
- 点击一组后跳转到对应问题，并把该组标记为已读。
- 动态来源包括新讨论或回复、消息被采纳、参与关系变化和问题状态变化。

## 首版暂不实现

- 私信
- 复杂通知偏好
- 自动状态级联或自动推导
- 形式化证明验证
- DAG、独立工作区和版本管理系统
- 问题管理者的其他权限

## 运行与部署

- 开发环境和生产演练都提供 Docker 配置，应用依赖与本地数据库不依赖宿主机安装。
- 本地 D1 与头像对象存储状态保存在 Docker 命名卷中；设计阶段归档不进入镜像。
- 生产容器运行正式构建后的 Worker 包，使本地演练与云端 D1 绑定保持同一种运行模型。
